Fair engine comparison: the archive scene

The archive's box-drop scene (boxes of 0.4 m fall from 40 m onto a 60 × 60 m floor, 8 batches of 10–100 per simulated second), run under one protocol in five setups. Physics steps a fixed 1/60 s, never tied to the wall clock. Every Jolt setup gets the same number of worker threads; Rapier and Avian run on the main thread only, because neither has browser threads out of the box. A run is broken if any box goes through the floor, or if more than half the boxes on the floor never fall asleep (the sign of Jolt's contact budget overflowing, which is what broke the archive's 10 000-box runs). If 1–50% are still awake when the 20 s settle window ends, the run counts but is marked slow to settle. The floor has no walls, as in the archive, so boxes knocked off its edge are counted separately and do not invalidate a run.

What is equal, and what is not

  • Same scene, spawn sequence (seeded mulberry32), materials (friction 0.5, restitution 0.1, damping 0.05, mass 1), gravity, step and sleeping in every setup. Godot's bounce is set to 0.05 per body because Godot adds the two values; damping uses REPLACE mode.
  • All three Jolt setups use the archive's contact budget (20480) and box convex radius 0.05. Three.js and Rust + Jolt run the same JoltPhysics.js 1.1.0 build; Godot runs its own built-in Jolt.
  • Threads: N means N Jolt worker threads plus the main thread. JoltPhysics.js caps it at hardware threads − 1; Godot uses N as its worker pool. Rapier and Avian always use the main thread only.
  • Rapier and Avian use their own solver defaults (Avian: 6 substeps), since iteration counts do not translate between solvers.
  • Sync copies only the bodies that moved, through each stack's natural API (Godot: the state-sync callback that RigidBody3D uses). In Godot, the step time includes Godot's own per-tick work around Jolt.
  • Rendering: one instanced box mesh, Lambert light, the same camera and canvas size, no shadows, no MSAA. "Draw" is CPU time to submit a frame, not GPU time.
